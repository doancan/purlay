# Purlay — Data Model (`SCHEMA.md`)

> Authority: `DECISIONS.md` explains *why*. This file is the normative definition of *what is
> stored*. If SQL here and prose elsewhere disagree, this file wins.
> Target: the PostgreSQL major named in `ARCHITECTURE.md` §2, which owns every version in the
> stack. Repeating it here is how one copy goes stale (D-20).
> Identifier columns carry an explicit `COLLATE "C"` so uniqueness never depends on the locale the
> server was provisioned with (D-40).

---

## 1. Storage Rules

1. **Tenant isolation is structural.** Every workspace-scoped table carries an indexed
   `workspace_id` (a test checks that every foreign key has an index, §6.2), and every query against those
   tables filters on it. There are no exceptions
   — which is precisely what makes the rule enforceable. (D-3, D-6)
2. **Content is soft-deleted, and soft deletion never cascades.** `deleted_at` is set and
   `content` is replaced with a tombstone. A deleted parent message does not take its thread
   with it. Hard deletion happens only in an operator-run purge. (D-9)
3. **`messages.id` is a UUIDv7 generated by the application.** The column has no default, so an
   insert that forgets to supply one fails loudly rather than silently producing an unorderable
   row. Every other table uses `gen_random_uuid()`. (D-8)
4. **Counters that appear in list views are denormalized.** Unread counts and thread reply
   counts are maintained columns, never `COUNT(*)` subqueries in a sidebar render. (D-13)
5. **Secrets are never stored in plaintext.** Session tokens are stored as SHA-256 hashes;
   third-party access tokens are encrypted with AES-256-GCM at the application layer.
   (D-11, D-23, D-39)
6. **Identifiers collate deterministically.** `channels.name`, `workspaces.slug`,
   `users.username` and `users.email` carry an explicit `COLLATE "C"`, so uniqueness and case
   folding never depend on the locale the server was provisioned with. (D-40)

## 3. Identity

### 3.1. `users`

Global account. Not workspace-scoped: one identity spans workspaces. (D-3)

```sql
CREATE TABLE users (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    -- Nullable for two reasons: Phase 2 magic-link accounts have no GitHub identity (D-11),
    -- and erasure clears this column so a returning person gets a new account rather than
    -- resurrecting the one they asked to have removed (D-38). UNIQUE permits many NULLs.
    github_id     BIGINT UNIQUE,

    -- The stable identity anchor across auth methods. Normalised to lowercase ASCII by the
    -- application; COLLATE "C" so comparison is byte-wise and identical everywhere. (D-40)
    email         TEXT COLLATE "C" NOT NULL UNIQUE,

    -- 39 characters is GitHub's maximum username length.
    username      VARCHAR(39) COLLATE "C" NOT NULL UNIQUE,
    display_name  VARCHAR(128) NOT NULL,
    avatar_url    TEXT,

    -- Best-effort, updated lazily. Live presence is in-memory and never persisted. (D-7)
    last_seen_at  TIMESTAMPTZ,

    -- The language this person's notifications are written in, set by their client (D-41, D-126).
    locale        TEXT NOT NULL DEFAULT 'en' CONSTRAINT users_locale_known CHECK (locale IN ('en', 'tr')),

    -- What a person says about themselves (D-131): each NULL until set, never blank. The time zone
    -- is an IANA name the service checks against its runtime; the database holds its length only.
    title         VARCHAR(80),
    time_zone     VARCHAR(64),
    status_text   VARCHAR(100),

    created_at    TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ  NOT NULL DEFAULT NOW(),

    -- Soft delete, so authorship on historical messages survives. (D-22)
    deleted_at    TIMESTAMPTZ,

    CONSTRAINT users_profile_not_blank CHECK (
        (title IS NULL OR btrim(title) <> '')
        AND (time_zone IS NULL OR btrim(time_zone) <> '')
        AND (status_text IS NULL OR btrim(status_text) <> '')
    )
);
```

### 3.2. `sessions`

Opaque bearer token in an `HttpOnly` cookie, validated against this table on every request and
on every WebSocket upgrade. Chosen over stateless JWT for revocability. (D-11)

```sql
CREATE TABLE sessions (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id      UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

    -- SHA-256 of the opaque token. The raw token exists only in the user's cookie:
    -- a database dump therefore does not hand over live sessions.
    token_hash   TEXT NOT NULL UNIQUE,

    user_agent   TEXT,
    ip_address   INET,

    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_used_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at   TIMESTAMPTZ NOT NULL,
    revoked_at   TIMESTAMPTZ
);

CREATE INDEX idx_sessions_user    ON sessions (user_id);
CREATE INDEX idx_sessions_expiry  ON sessions (expires_at) WHERE revoked_at IS NULL;
CREATE INDEX idx_sessions_revoked ON sessions (revoked_at) WHERE revoked_at IS NOT NULL;
```

`ip_address` is the client address at sign-in (the socket's peer, or the proxy-reported one under `TRUST_PROXY`; null if unknown). It is personal data: erasure nulls it with the session (D-27, D-81).

`last_used_at` is refreshed at most once an hour, not on every request: this table is read on every HTTP request and every socket upgrade, and a write there would be a write on the hottest path in the system. (D-60)

Expired and revoked rows are not kept: `purgeDeadSessions` removes them in bounded batches, called by the scheduler (#71). (D-87)

### 3.3. `push_subscriptions` and `users.locale`

A person's devices that are told, by Web Push, of what needs them while Purlay is closed (#78, D-126),
and the language the server writes those notices in (D-41).

```sql
CREATE TABLE push_subscriptions (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    -- The session it was made in: signing out deletes it, and a push needs the session live.
    session_id  UUID NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    -- The push service's address for this browser; unique across people, so a browser signed
    -- into another account moves to it rather than telling two.
    endpoint    TEXT NOT NULL UNIQUE,
    p256dh      TEXT NOT NULL,   -- the browser's P-256 point, validated as one on the way in
    auth        TEXT NOT NULL,   -- its 16-byte secret (RFC 8291)
    -- The application-server key it was made with: after the operator changes it, inert.
    server_key  TEXT NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    failures    INTEGER NOT NULL DEFAULT 0,   -- deliveries in a row the push service did not take

    CONSTRAINT push_subscriptions_endpoint_is_https CHECK (endpoint LIKE 'https://%'),
    CONSTRAINT push_subscriptions_endpoint_bounded CHECK (length(endpoint) <= 2048),
    CONSTRAINT push_subscriptions_failures_counted CHECK (failures >= 0)
);

CREATE INDEX idx_push_subscriptions_user    ON push_subscriptions (user_id, created_at);
CREATE INDEX idx_push_subscriptions_session ON push_subscriptions (session_id);
```

At most 20 devices a person, the least recently subscribed dropped when a twenty-first subscribes
(subscribing again sets `created_at`). A row moves to another person only when they send its keys
as well as its endpoint. A session's rows go when it is revoked (sign-out, sign out everywhere), in
the same transaction, and, with the session, when `purgeDeadSessions`
removes it. The endpoint and both keys are a person's: never logged (`ARCHITECTURE.md` §10).

### 3.4. `email_sign_ins`

Every message sent to sign in by email (migration 0038, D-138): a link, or a word that the address signs
in with GitHub.

```sql
CREATE TABLE email_sign_ins (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email       TEXT NOT NULL,                     -- lower-cased, as every stored address (D-40)
    kind        TEXT NOT NULL,                     -- 'link' | 'github'
    token_hash  TEXT UNIQUE,                       -- SHA-256 of a link's token; never the token
    created_at  TIMESTAMPTZ NOT NULL,
    expires_at  TIMESTAMPTZ NOT NULL,              -- fifteen minutes after
    used_at     TIMESTAMPTZ,                       -- set by the one use

    CONSTRAINT email_sign_ins_email_lower CHECK (email = lower(email) AND char_length(email) <= 254),
    CONSTRAINT email_sign_ins_kind CHECK (kind IN ('link', 'github')),
    CONSTRAINT email_sign_ins_token_hash CHECK (
        (kind = 'link') = (token_hash IS NOT NULL) AND (token_hash IS NULL OR token_hash ~ '^[0-9a-f]{64}$')
    ),
    CONSTRAINT email_sign_ins_expiry CHECK (expires_at > created_at)
);

CREATE INDEX idx_email_sign_ins_email ON email_sign_ins (email, created_at);
```

> No user id: a link to an address no account has makes the account on its use. Both kinds count
> toward the address's five an hour, so neither can flood a mailbox. A day after, a row is swept
> (`sweep:email-sign-ins`); erasure (D-27) deletes a person's as it rewrites their address.

## 4. Workspaces & Membership

### 4.1. `workspaces`

```sql
CREATE TABLE workspaces (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name        VARCHAR(64) NOT NULL,
    -- COLLATE "C": a slug is an identifier, not prose. (D-40)
    slug        VARCHAR(64) COLLATE "C" NOT NULL UNIQUE,
    avatar_url  TEXT,

    -- Audit only. Ownership is workspace_members.role = 'owner'. (D-22)
    created_by  UUID REFERENCES users(id) ON DELETE SET NULL,

    -- Self-hosters pay for the disk, so uploads are capped per workspace. (D-16)
    storage_quota_bytes BIGINT NOT NULL DEFAULT 5368709120,  -- 5 GiB
    storage_used_bytes  BIGINT NOT NULL DEFAULT 0,

    -- NULL means infinite, which is the default and the product's tenet: nothing is
    -- thrown away. An operator opts in; the purge job (D-30) enforces it. (D-27)
    retention_days      INTEGER,

    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at  TIMESTAMPTZ,

    CONSTRAINT storage_used_non_negative CHECK (storage_used_bytes >= 0),

    -- A floor, not a preference. A typo of `1` in a retention field would delete a
    -- team's memory overnight and no correct value is that small. (D-27)
    CONSTRAINT retention_days_sane
        CHECK (retention_days IS NULL OR retention_days >= 30)
);

-- No index on `slug`: the UNIQUE constraint above already is one, and a second, partial one
-- only made every write to this table pay twice. Dropped by 0009. (D-89)

-- The foreign key's index (see §6.2).
CREATE INDEX idx_workspaces_created_by ON workspaces (created_by) WHERE created_by IS NOT NULL;
```

### 4.2. `workspace_members`

The tenancy binding, and the row Deep Work lives on. (D-15)

```sql
CREATE TABLE workspace_members (
    id           UUID NOT NULL PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    user_id      UUID NOT NULL REFERENCES users(id)      ON DELETE CASCADE,
    role         user_role NOT NULL DEFAULT 'member',

    -- Server-side, so it holds across devices and so the server itself stops
    -- delivering. A purely client-side mute would still wake a phone. (D-15)
    is_deep_work_active BOOLEAN NOT NULL DEFAULT FALSE,
    deep_work_until     TIMESTAMPTZ,

    joined_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE (workspace_id, user_id)
);

CREATE INDEX idx_workspace_members_user ON workspace_members (user_id);

-- Every workspace must retain at least one owner. Not expressible as a constraint;
-- enforced in the membership service and covered by a test. (D-21)
```

### 4.3. `workspace_invitations`

The links that let a person in (D-115). Only the token's digest is kept, as a session's is; a link is
revoked by setting `revoked_at`, never by deleting the row, which stays the record of what was handed
out. Who joined by which link is in `audit_log` (`member.joined`, `metadata.invitationId`), so a join
writes no counter here.

```sql
CREATE TABLE workspace_invitations (
    id            UUID PRIMARY KEY,
    workspace_id  UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
    token_hash    TEXT NOT NULL UNIQUE,
    created_by    UUID REFERENCES users(id) ON DELETE SET NULL,
    created_at    TIMESTAMPTZ NOT NULL,
    expires_at    TIMESTAMPTZ NOT NULL,
    revoked_at    TIMESTAMPTZ,

    CONSTRAINT workspace_invitations_id_is_uuidv7
        CHECK (id::text ~ '^[0-9a-f]{8}-[0-9a-f]{4}-7[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$'),
    CONSTRAINT workspace_invitations_token_is_a_digest CHECK (token_hash ~ '^[0-9a-f]{64}$'),
    CONSTRAINT workspace_invitations_expire_after_made CHECK (expires_at > created_at)
);

CREATE INDEX idx_workspace_invitations_workspace ON workspace_invitations (workspace_id, id DESC);
CREATE INDEX idx_workspace_invitations_created_by ON workspace_invitations (created_by)
    WHERE created_by IS NOT NULL;
```

## 5. Channels

### 5.1. `channels`

Public channels, private channels and DMs share one table. What separates them is `type`, and
two CHECK constraints keep each shape honest. (D-6)

```sql
CREATE TABLE channels (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,

    -- NULL for DMs, which are identified by their members, not by a name.
    -- COLLATE "C" so that lower(name) folds identically on every deployment: under a Turkish
    -- locale lower('İ') does not produce 'i', and channel-name uniqueness would otherwise
    -- depend on how the server was provisioned. (D-40)
    name         VARCHAR(64) COLLATE "C",
    topic        TEXT,
    type         channel_type NOT NULL DEFAULT 'public',

    -- Sorted, colon-joined user UUIDs of the conversation's people (two, or up to ten for a
    -- group, D-127). Set only for DMs; the partial unique index below uses it to stop a second
    -- conversation opening between the same people.
    dm_key       TEXT,

    created_by   UUID REFERENCES users(id) ON DELETE SET NULL,

    -- Denormalized so the sidebar can order channels without touching `messages`.
    last_message_at TIMESTAMPTZ,

    -- The channel's own count of its renames, raised in the statement that renames under the row
    -- lock: `CHANNEL_UPDATED` carries it and a client drops an older one (0023, D-123).
    state_version INTEGER NOT NULL DEFAULT 0,

    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    -- Archived (D-123): hidden from everyone, its messages and memberships kept, its name free.
    deleted_at   TIMESTAMPTZ,

    CONSTRAINT named_unless_dm CHECK (
        (type = 'direct_message' AND name IS NULL)
        OR (type <> 'direct_message' AND name IS NOT NULL)
    ),
    CONSTRAINT dm_key_iff_dm CHECK (
        (type = 'direct_message') = (dm_key IS NOT NULL)
    ),

    -- Two lower-case member ids, the first not above the second byte-wise, joined with ':'.
    -- Added by 0010 for two people, replaced by 0025 for two to ten (a group conversation, D-127);
    -- each NOT VALID then validated. Two ids may be equal (a note to self); three or more are
    -- strictly ascending, `member_key_is_sorted` comparing them byte for byte. (I-5, D-90)
    CONSTRAINT dm_key_form CHECK (dm_key IS NULL
        OR (dm_key ~ '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}(:[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}){1,9}$'
            AND public.member_key_is_sorted(dm_key))),

    -- The target of the composite keys below: a message names its channel *and* the
    -- channel's workspace, and the database checks that they belong together. (D-90)
    CONSTRAINT channels_id_workspace_id_key UNIQUE (id, workspace_id)
);

-- Channel names are unique per workspace, case-insensitively, and only among
-- live named channels. Deleting #api frees the name for reuse.
CREATE UNIQUE INDEX idx_channels_unique_name
    ON channels (workspace_id, lower(name))
    WHERE type <> 'direct_message' AND deleted_at IS NULL;

-- One DM per pair per workspace.
CREATE UNIQUE INDEX idx_channels_unique_dm
    ON channels (workspace_id, dm_key)
    WHERE type = 'direct_message';

-- Deliberately not ordered by last_message_at: every send writes that column, and a column
-- in an index cannot be changed by a heap-only update. The sidebar sorts what this finds. Not
-- partial, because it is also the index the foreign key to workspaces needs. (D-88)
CREATE INDEX idx_channels_workspace
    ON channels (workspace_id);

-- The foreign key's index (see §6.2).
CREATE INDEX idx_channels_created_by ON channels (created_by) WHERE created_by IS NOT NULL;
```

`last_message_at` is only ever moved forward, and only by a send that is newer than the value it holds; a
send that is not the newest writes nothing. It is the one column of this table that changes on the hot
path, which is why it is in no index. (D-88)

### 5.2. `channel_members`

Membership, read position, unread counters and per-channel notification level.

```sql
CREATE TABLE channel_members (
    id         UUID NOT NULL PRIMARY KEY DEFAULT gen_random_uuid(),
    channel_id UUID NOT NULL REFERENCES channels(id) ON DELETE CASCADE,
    user_id    UUID NOT NULL REFERENCES users(id)    ON DELETE CASCADE,

    -- Keyed together with channel_id below: a read position is a message of *this* channel.
    last_read_message_id UUID,

    -- Maintained on write. A COUNT(*) per channel per sidebar render is the
    -- N+1 the project rules forbid. (D-13)
    unread_count         INTEGER NOT NULL DEFAULT 0,
    unread_mention_count INTEGER NOT NULL DEFAULT 0,

    -- Counts this row's changes to the state above, in the statement that makes them, so the
    -- order of versions is the order of commits. `CHANNEL_STATE` carries it and a client drops
    -- a frame that is not newer than the one it holds. Added by 0015. (D-99, amended)
    state_version        INTEGER NOT NULL DEFAULT 0,

    -- Defaults to 'mentions': quiet by default is the product, not a preference. (D-12)
    notification_level notification_level NOT NULL DEFAULT 'mentions',

    -- When the member starred it; NULL while they have not (D-132). Added by 0030.
    starred_at TIMESTAMPTZ,

    joined_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE (channel_id, user_id),
    CONSTRAINT unread_counts_non_negative
        CHECK (unread_count >= 0 AND unread_mention_count >= 0),

    -- I-6. What needs you is, first, something you have not read. Added by 0013, NOT VALID
    -- then validated, once the service that defines a counted mention existed. (D-99)
    CONSTRAINT unread_mention_within_unread
        CHECK (unread_mention_count <= unread_count),

    -- I-3. SET NULL names its column: the plain form would also null `channel_id`, which a
    -- membership cannot exist without. Added by 0010, NOT VALID then validated. (D-90)
    CONSTRAINT channel_members_last_read_channel_fkey
        FOREIGN KEY (last_read_message_id, channel_id) REFERENCES messages (id, channel_id)
        ON DELETE SET NULL (last_read_message_id)
);

CREATE INDEX idx_channel_members_user ON channel_members (user_id);

-- Deleting a message asks which memberships last read it (ON DELETE SET NULL). (D-89)
CREATE INDEX idx_channel_members_last_read
    ON channel_members (last_read_message_id) WHERE last_read_message_id IS NOT NULL;
```

> **Ordering note.** `channel_members` references `messages`, and `messages` references
> `channels`. The migration therefore creates `channels`, then `messages`, then
> `channel_members` — or adds the `last_read_message_id` foreign key in a later statement.

## 6. Messages & Threads

### 6.1. `messages`

The hot table. Everything about it is shaped by read patterns.

```sql
CREATE TABLE messages (
    -- No DEFAULT: the application supplies a UUIDv7. An insert that forgets one
    -- fails loudly instead of silently creating an unorderable row. (D-8)
    id           UUID PRIMARY KEY,

    workspace_id UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,

    -- Keyed together with workspace_id below: a message is in the workspace of its channel.
    channel_id   UUID NOT NULL,

    -- RESTRICT, because users are soft-deleted and authorship must survive. (D-22)
    -- NULL for a message nobody wrote: a repository's event (`messages_sender_by_type`, 0032, D-134).
    sender_id    UUID REFERENCES users(id) ON DELETE RESTRICT,

    -- Threads are exactly two levels deep: a root message and its replies.
    -- A reply may not itself be a parent. Enforced in the message service.
    -- Keyed together with channel_id below: a reply is in its parent's channel.
    parent_id    UUID,

    -- Denormalized thread summary, so rendering a feed of 50 root messages
    -- does not become 50 extra queries.
    thread_reply_count   INTEGER NOT NULL DEFAULT 0,
    thread_last_reply_at TIMESTAMPTZ,

    -- Counts changes to the thread summary, the reaction set and the content (an edit, D-103),
    -- in the statement that makes them, so versions are in commit order; `THREAD_UPDATED` and
    -- `REACTIONS_UPDATED` carry it. Added by 0015. (D-99, amended)
    state_version        INTEGER NOT NULL DEFAULT 0,

    -- The wedge: a thread can be closed, and stays searchable. (D-2)
    resolved_at  TIMESTAMPTZ,
    resolved_by  UUID REFERENCES users(id) ON DELETE SET NULL,

    content      TEXT NOT NULL,
    message_type message_type NOT NULL DEFAULT 'text',

    -- Renderer hints and system-event payloads, read by `message_type`, never by their shape: a
    -- `text` message's `TextMetadata`, a `system_event`'s `GitHubEvent` ('{}' once it is a
    -- tombstone). Never used for tenant filtering.
    metadata     JSONB NOT NULL DEFAULT '{}'::jsonb,

    edited_at    TIMESTAMPTZ,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at   TIMESTAMPTZ,

    -- A person's message has its sender; an event has none. Added by 0032. (D-134 §6)
    CONSTRAINT messages_sender_by_type CHECK ((message_type = 'text') = (sender_id IS NOT NULL)),
    -- An event's metadata names a kind the contract knows, or is '{}' as a tombstone. Added by 0032.
    CONSTRAINT messages_event_known CHECK (
        message_type = 'text'
        OR metadata = '{}'::jsonb
        OR metadata ->> 'kind' IN ('push', 'pull_request', 'issues', 'release')
    ),

    -- Only root messages are resolvable; resolving a reply is meaningless.
    CONSTRAINT only_roots_resolve CHECK (parent_id IS NULL OR resolved_at IS NULL),

    -- Resolution is all-or-nothing: never a timestamp without an actor.
    CONSTRAINT resolution_is_complete
        CHECK ((resolved_at IS NULL) = (resolved_by IS NULL)),

    -- Replies have no thread summary of their own.
    CONSTRAINT replies_have_no_thread_summary
        CHECK (parent_id IS NULL OR thread_reply_count = 0),

    CONSTRAINT thread_reply_count_non_negative CHECK (thread_reply_count >= 0),

    -- The contract's MESSAGE_CONTENT_MAX, for every writer that is not one of the
    -- two doors, in UTF-16 code units as the contract counts them: characters, plus one more
    -- for each outside the Basic Multilingual Plane. Added by 0007 as characters and replaced
    -- by 0011 with the units. (D-67, D-86)
```

### 6.2. Indexes

```sql
-- Primary feed. Keyset pagination on `id` alone: UUIDv7 is byte-wise time-ordered,
-- and PostgreSQL compares the uuid type byte-wise, so this index IS chronological.
-- Root messages only, because thread replies are read with their root, in its thread (D-8, D-122).
-- A deleted root with replies keeps its place, as its tombstone (D-103 §7). Redefined by 0016.
CREATE INDEX idx_messages_channel_feed
    ON messages (channel_id, id DESC)
    WHERE parent_id IS NULL AND (deleted_at IS NULL OR thread_reply_count > 0);

-- Expanding one thread: every reply, a deleted one as its tombstone (D-103 §7). Redefined by 0016.
CREATE INDEX idx_messages_thread
    ON messages (parent_id, id)
    WHERE parent_id IS NOT NULL;

-- Scoped substring / identifier search. btree_gin lets workspace_id sit inside the
-- GIN index, so the trigram scan is confined to one tenant instead of the whole table. (D-10)
CREATE INDEX idx_messages_search
    ON messages USING gin (workspace_id, content gin_trgm_ops)
    WHERE deleted_at IS NULL;

-- "Messages by this user", and the guard against orphaned RESTRICT references.
CREATE INDEX idx_messages_sender ON messages (sender_id);

-- Open questions across a workspace: the resolvable-thread feature's own view.
-- Only roots that have a reply: nearly every root has none, and an index of all of them made
-- a view that wants the rare ones read them all (6,975 buffers against 41 on 400,000 messages).
-- Redefined by 0014.
CREATE INDEX idx_messages_unresolved
    ON messages (workspace_id, id DESC)
    WHERE parent_id IS NULL AND resolved_at IS NULL AND deleted_at IS NULL
      AND thread_reply_count > 0;

-- The foreign keys. The indexes above are partial, and the query that enforces a foreign key
-- filters on the column alone, so none of them can answer it. Without these, deleting 100 of
-- 1,000,000 messages took 4.9 s and deleting a channel did not finish in 60 s. (D-89)
CREATE INDEX idx_messages_channel     ON messages (channel_id);
CREATE INDEX idx_messages_parent      ON messages (parent_id)   WHERE parent_id IS NOT NULL;
CREATE INDEX idx_messages_resolved_by ON messages (resolved_by) WHERE resolved_by IS NOT NULL;

-- The retention purge's read: one workspace's messages older than its window, from the oldest
-- (D-139 §1). By workspace alone, a night would walk the workspace's whole history once a batch.
-- Added by 0039, which dropped `idx_messages_workspace (workspace_id)`: this one leads with the same
-- column, so it serves the foreign key too.
CREATE INDEX idx_messages_workspace_age ON messages (workspace_id, created_at);
```

**Every foreign key column leads an index the planner can use for it**, and a test reads the catalogue to
prove it, so a table added later cannot forget one. A nullable column is indexed only where it is set,
which is all a lookup by value needs. Measured on 1,000,000 messages (10 workspaces, 200 channels,
200 users):

| | before | after |
|---|---|---|
| `DELETE` of 100 messages | 4,756 ms | 8.7 ms |
| `DELETE` of one channel (5,000 messages, cascading) | did not finish in 60 s | 90 ms |
| the four new `messages` indexes, on disk | | 14 MB over 376 MB of indexes |
| 20,000 single-row inserts | 1,107 ms | 1,168 ms (+5 %) |

**The search index is the expensive one, and it stays.** `idx_messages_search` is 206 MB of the 376 MB the
table's indexes occupy, and removing it made 20,000 single-row inserts 1.8 times as fast on
high-entropy text (1,107 ms against 613 ms) and 1.45 to 1.6 times on prose (892 and 1,036 ms against 607
and 651). That is about 15 to 25 µs a message, which is invisible at the rate a team sends and is the price
of substring search (D-10) without a second system. It is written down so that it is a choice: it is
reopened when insert latency shows up in a measurement of the send path, or when search moves out of
the database.

### 6.3. Pagination Contract

```sql
-- Newest page
SELECT * FROM messages
 WHERE channel_id = $1 AND parent_id IS NULL AND deleted_at IS NULL
 ORDER BY id DESC
 LIMIT 50;

-- Older page: the cursor is the last id seen. No timestamp, no offset, no tie-break.
SELECT * FROM messages
 WHERE channel_id = $1 AND parent_id IS NULL AND deleted_at IS NULL
   AND id < $2
 ORDER BY id DESC
 LIMIT 50;
```

`OFFSET` is prohibited on this table: it is O(n) and shifts under concurrent inserts, which in
a live channel is *every* page.

and swept by a periodic job. (D-23)

```sql
CREATE TABLE link_previews (
    -- SHA-256 of the normalized URL. Fixed width, and safe as a key regardless of URL length.
    url_hash    TEXT PRIMARY KEY,
    url         TEXT NOT NULL,

    -- GitHubCardMetadata, or a negative-cache marker so a 404 is not re-fetched
    -- on every paste.
    payload     JSONB NOT NULL,

    fetched_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at  TIMESTAMPTZ NOT NULL
);

CREATE INDEX idx_link_previews_expiry ON link_previews (expires_at);
```

> No `workspace_id` column, but scoped by its key: `url_hash` is the hash of the workspace and the
> URL, so a card fetched with one workspace's token — a private repository's included — is that
> workspace's alone (D-112).

### 8.3. `github_repo_feeds` and `github_deliveries`

A repository's feed into a channel, and the deliveries it has posted (migration 0031, D-134).

```sql
CREATE TABLE github_repo_feeds (
    id                   UUID PRIMARY KEY,               -- given before the seal, bound into it
    workspace_id         UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    channel_id           UUID NOT NULL,
    repository_full_name VARCHAR(140) COLLATE "C" NOT NULL,  -- 'org/repo', lower case
    repository_id        BIGINT,                         -- learnt from the first delivery
    events               TEXT[] NOT NULL,                -- push, pull_request, issues, release
    secret_encrypted     TEXT NOT NULL,                  -- the webhook secret, sealed (D-39 §6)
    created_by           UUID REFERENCES users(id) ON DELETE SET NULL,
    created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_delivery_at     TIMESTAMPTZ,
    last_failure         VARCHAR(64),                    -- a GitHubFeedFailure, with its time
    last_failure_at      TIMESTAMPTZ,

    CONSTRAINT github_repo_feeds_repository_shape CHECK (
        repository_full_name ~ '^[a-z0-9][a-z0-9-]{0,38}/(?!\.\.?$)[a-z0-9._-]{1,100}$'
    ),
    CONSTRAINT github_repo_feeds_events_known CHECK (
        cardinality(events) >= 1
        AND events <@ ARRAY['push', 'pull_request', 'issues', 'release']::TEXT[]
    ),
    CONSTRAINT github_repo_feeds_failure_known CHECK (   -- 'rate_limited' added by 0033
        last_failure IN ('channel_archived', 'repository_mismatch', 'payload_invalid', 'rate_limited')
    ),
    CONSTRAINT github_repo_feeds_failure_is_complete CHECK (
        (last_failure IS NULL) = (last_failure_at IS NULL)
    ),
    CONSTRAINT github_repo_feeds_channel_repository_key UNIQUE (channel_id, repository_full_name),
    CONSTRAINT github_repo_feeds_channel_workspace_fkey
        FOREIGN KEY (channel_id, workspace_id) REFERENCES channels (id, workspace_id)
        ON DELETE CASCADE
);

CREATE INDEX idx_github_repo_feeds_workspace ON github_repo_feeds (workspace_id);
CREATE INDEX idx_github_repo_feeds_created_by ON github_repo_feeds (created_by)
    WHERE created_by IS NOT NULL;

CREATE TABLE github_deliveries (
    feed_id      UUID NOT NULL REFERENCES github_repo_feeds(id) ON DELETE CASCADE,
    delivery_id  VARCHAR(64) COLLATE "C" NOT NULL,       -- X-GitHub-Delivery
    received_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),     -- swept after 30 days
    PRIMARY KEY (feed_id, delivery_id)
);

CREATE INDEX idx_github_deliveries_received ON github_deliveries (received_at);
```

> A feed is its channel's, in its channel's workspace (I-4), and goes with either. The secret is never
> returned after the answer that made it and never logged (`ARCHITECTURE.md` §10). A delivery is
> recorded in the transaction that posts it, so the same delivery again posts nothing.

## 9. Administration & Operations

Two tables that exist to make administrative action and scheduled work *visible*. Neither holds
message content. (D-26, D-30)

### 9.1. `audit_log`

Append-only. The application role holds `INSERT` on this table and nothing else; a test asserts
no service issues `UPDATE` or `DELETE` against it. (D-26)

```sql
CREATE TABLE audit_log (
    -- Application-supplied UUIDv7, for the same reason as `messages`: the trail is read
    -- newest-first with keyset pagination and needs a stable cursor. (D-8)
    id            UUID PRIMARY KEY,

    -- RESTRICT: the record outlives the thing it describes. A workspace is soft-deleted
    -- (deleted_at), so this never fires in normal operation — it exists to make a hard
    -- purge that would erase the audit trail fail loudly.
    workspace_id  UUID NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,

    -- Kept when the actor is erased: their row stays, anonymised (D-139 §5). What was
    -- done survives who did it.
    actor_user_id UUID REFERENCES users(id) ON DELETE SET NULL,

    -- Stable machine-readable verb: 'member.role_changed', 'integration.token_set',
    -- 'retention.purged', 'account.erased'. Never derived from user input.
    action        VARCHAR(64) NOT NULL,
    target_type   VARCHAR(32) NOT NULL,
    target_id     UUID,

    -- The session the act was made with: through it the sign-in's address and agent, for as long
    -- as the session is kept; NULL once it is swept, and for what no request did (D-116).
    session_id    UUID REFERENCES sessions(id) ON DELETE SET NULL,

    -- Changed fields, before and after. Never message content, never a token,
    -- never an email address. (`ARCHITECTURE.md` §10)
    metadata      JSONB NOT NULL DEFAULT '{}'::jsonb,

    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT audit_log_id_is_uuidv7
        CHECK (id::text ~ '^[0-9a-f]{8}-[0-9a-f]{4}-7[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$')
);

-- The admin view: one workspace's trail, newest first.
CREATE INDEX idx_audit_log_workspace ON audit_log (workspace_id, id DESC);

-- "What did this account do", needed to answer an erasure request before honouring it.
CREATE INDEX idx_audit_log_actor ON audit_log (actor_user_id, id DESC)
    WHERE actor_user_id IS NOT NULL;

CREATE INDEX idx_audit_log_session ON audit_log (session_id) WHERE session_id IS NOT NULL;
```

No `updated_at` and no `deleted_at`: a row that can be amended is not an audit record.

### 9.2. `job_runs`

One row per scheduled job, upserted on every run. It exists for exactly one reason: an external
scheduler (D-30) that was never installed fails **silently**, and this table is what makes that
failure visible — via `purlay jobs:status` in Phase 1, and the operator dashboard in Phase 2.
There is no HTTP endpoint for it in Phase 1: the data is instance-wide, and exposing it would
require an instance-administrator role that does not exist and that D-3 deliberately avoided.

```sql
CREATE TABLE job_runs (
    -- 'sweep:orphans', 'sweep:link-previews', 'sweep:sessions', 'sweep:github-deliveries',
    -- 'sweep:email-sign-ins', 'sweep:exports', 'sweep:deletions',
    -- 'reconcile:storage', 'purge:retention'
    job_name             VARCHAR(64) PRIMARY KEY,

    last_started_at      TIMESTAMPTZ,
    last_success_at      TIMESTAMPTZ,
    last_duration_ms     INTEGER,

    -- Truncated message only. A stack trace belongs in the log, not in a table
    -- an admin screen renders.
    last_error           TEXT,
    consecutive_failures INTEGER NOT NULL DEFAULT 0,

    CONSTRAINT consecutive_failures_non_negative CHECK (consecutive_failures >= 0)
);
```

Deliberately **not** workspace-scoped: these jobs are instance-wide, and `/health/ready` does not
consult this table — a stale sweep is an operational warning, not a reason to stop serving
traffic.

### 9.3. `workspace_exports`

An owner's export of their workspace (D-140): asked for, made in the background, downloaded once. The
row is the record that it was made; its archive lives in the object store under the workspace's prefix
until it is downloaded or expires (`sweep:exports`). Never exported itself.

```sql
CREATE TABLE workspace_exports (
    id             UUID PRIMARY KEY,
    workspace_id   UUID NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
    requested_by   UUID REFERENCES users(id) ON DELETE SET NULL,
    -- 'pending' while it is made, 'ready' with its archive, 'failed' with a code,
    -- 'downloaded' once it has been, 'expired' when nobody did in time.
    status         TEXT NOT NULL,
    storage_key    TEXT,
    size_bytes     BIGINT,
    failure        TEXT,
    created_at     TIMESTAMPTZ NOT NULL,
    finished_at    TIMESTAMPTZ,
    -- Every minute while it is made: one silent for long was cut off by a restart.
    heartbeat_at   TIMESTAMPTZ,
    expires_at     TIMESTAMPTZ,
    downloaded_at  TIMESTAMPTZ,

    CONSTRAINT workspace_exports_id_is_uuidv7
        CHECK (id::text ~ '^[0-9a-f]{8}-[0-9a-f]{4}-7[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$'),
    CONSTRAINT workspace_exports_status
        CHECK (status IN ('pending', 'ready', 'failed', 'downloaded', 'expired')),
    -- The key stays on a downloaded or expired row until the object is gone.
    CONSTRAINT workspace_exports_ready
        CHECK (status <> 'ready'
               OR (storage_key IS NOT NULL AND size_bytes IS NOT NULL AND expires_at IS NOT NULL)),
    CONSTRAINT workspace_exports_pending
        CHECK (status <> 'pending' OR storage_key IS NULL),
    CONSTRAINT workspace_exports_failure
        CHECK ((status = 'failed') = (failure IS NOT NULL) AND (failure IS NULL OR failure ~ '^[A-Z_]{1,64}$'))
);

-- One export of a workspace in the making at a time.
CREATE UNIQUE INDEX idx_workspace_exports_one_pending
    ON workspace_exports (workspace_id) WHERE status = 'pending';

-- The owner's list, newest first.
CREATE INDEX idx_workspace_exports_workspace ON workspace_exports (workspace_id, id DESC);
CREATE INDEX idx_workspace_exports_requested_by
    ON workspace_exports (requested_by) WHERE requested_by IS NOT NULL;
```

### 9.4. `object_deletions`

Objects in the store whose rows are gone, until the store has let them go (D-141). A key is written in
the transaction that deletes the rows naming it — `dropFiles` for retention and erasure, the orphan
sweep, a discarded upload — so a refusal, or a process stopping between the commit and the delete, never
loses it. The row goes once the store has deleted the object; `sweep:deletions` tries what is left
every hour, in key order from where it got to. Instance-wide, like `job_runs`: an operator's table, read
by no endpoint, and never exported.

```sql
CREATE TABLE object_deletions (
    storage_key      TEXT PRIMARY KEY,
    enqueued_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    attempts         INTEGER NOT NULL DEFAULT 0,
    last_attempt_at  TIMESTAMPTZ,

    CONSTRAINT object_deletions_key_in_a_workspace CHECK (storage_key LIKE 'w/%'),
    CONSTRAINT object_deletions_attempts CHECK (attempts >= 0)
);
```

## 10. Kysely Types (`packages/db/src/schema.ts`)

**Generated** by `kysely-codegen` from a database with every migration applied, and committed so
that typechecking never needs a running database. The migrations are the single source; the types
are derived, so drift is not detected — it is impossible. CI regenerates and requires an empty
diff. (D-45)

The shape below is what the generator produces once the `CreatedAt`, `UpdatedAt` and `Json<T>`
overrides are configured. It is reproduced here because this document is where the data model is
read, **not** because it is maintained here: editing it by hand is a defect the CI check will
reject.

```typescript
// packages/db/src/schema.ts — generated, never edited
export interface DB {
  users: Users;
  sessions: Sessions;
  workspaces: Workspaces;
  workspace_members: WorkspaceMembers;
  channels: Channels;
  messages: Messages;
  channel_members: ChannelMembers;
  // …one entry per applied migration's tables
}
```

The generator names the root interface `DB`; `@purlay/db` re-exports it as `Database`, which is
the name the rest of the documents use (`ARCHITECTURE.md` §10, D-46). That is an alias, not a
second definition.

**Three things a reader should know, because the generator's output is not obvious:**

- `BIGINT` arrives as a **string**, not a number — `storage_quota_bytes`, `storage_used_bytes` and
  `attachments.size_bytes`. JavaScript's number cannot hold the range, so the driver refuses to
  narrow it.
- **`messages.id` is not `Generated`.** The column has no default, so the generator types it as
  required on insert — which is exactly the loud failure D-8 asked for: an insert that forgets the
  application's UUIDv7 does not compile.
- `JSONB` columns are a `ColumnType` with different read and write shapes: an object on the way
  out, a serialised string on the way in.

A full listing is not reproduced here. It would be a copy of a generated file, and the last
consistency pass spent its time removing exactly that kind of copy. `bun run db:generate`
regenerates it; CI fails on any diff.

## 11. Invariants

Rules the schema cannot express. Each has a named test. (D-21)

| # | Invariant | Enforced in |
|---|---|---|
| I-1 | Threads are at most two levels deep: a reply's `parent_id` must point at a message whose own `parent_id` is `NULL`. The database enforces that a reply is in its parent's channel (and so workspace); depth is the service's. | `messages.service`, in part `messages_parent_channel_fkey` |
| I-2 | Every workspace has at least one live `owner` — an erased one counts for nothing. The last live owner cannot be demoted, removed, or erase their account while another live member remains. | `workspaces/members.ts`, `users/erasure.ts`, under the workspace row's lock (D-111, D-139 §6) |
| I-3 | `channel_members.last_read_message_id` must belong to that channel. | the database: `channel_members_last_read_channel_fkey` |
| I-4 | `messages.workspace_id` must equal the `workspace_id` of its `channel_id`. Denormalized for the tenant guard; must never diverge. | the database: `messages_channel_workspace_fkey` |
| I-5 | `dm_key` is the UUIDs of the conversation's people — two, or up to ten for a group (D-127) — sorted ascending and joined with `:`; the same set is the same conversation. The database enforces the form and the order; that they are people of the workspace is the service's. | `channels.service`, in part `dm_key_form` |
| I-6 | `unread_count` ≥ `unread_mention_count` for every membership row. | the database: `unread_mention_within_unread` (D-99) |
| I-7 | `workspaces.storage_used_bytes` equals the sum of the sizes of the attachments messages carry. Kept by the send that links them; reconciled nightly by `bun run job reconcile:storage`. | `messages.ts` `linkAttachments`, `jobs.ts` `reconcileStorage` |
| I-8 | A resolved thread's root has `parent_id IS NULL` and `thread_reply_count > 0`. | `threads.service` |
| I-9 | `audit_log` is append-only: no service issues `UPDATE` or `DELETE` against it. | `audit/audit.ts`; held by `audit/append-only.test.ts` |
| I-10 | The retention purge deletes nothing when `retention_days IS NULL`, and never a message newer than the window. Every run writes one `audit_log` entry for each workspace with retention set (D-139 §3). | `modules/retention/purge.ts` |
| I-11 | An erased user has no personal data on `users`, no live session, **no `github_id`**, and every message they authored still exists. Erasure never cascades, and a later sign-in creates a new account rather than resurrecting the erased one. (D-27, D-38, D-139 §5) | `modules/users/erasure.ts` |

**What the database enforces, and what stays with the service.** I-3, I-4 and I-6 are constraints now (the
last with the read-state service, D-99), and I-1 and I-5 are constraints in part (D-90). Four things stay service-level on purpose:

- **Thread depth (I-1, the rest).** A reply's parent must itself be a root. A foreign key cannot say
  "the row I point at has a null column"; it takes a trigger, or a stored generated column on a table of
  millions of rows (a rewrite under an exclusive lock). The tenant half of I-1, that a reply never leaves its
  parent's channel, is the part a leak depends on, and that is in the database.
- **Counters kept equal to other rows (`thread_reply_count`, I-7, I-8).** A maintained count equal to a count
  of other rows is a trigger, and a trigger on the hottest table is a cost this schema has not been shown to
  need. The service maintains them in the send's transaction; a nightly reconcile is the check. A
  `thread_reply_count` of 999 on a message with no replies is accepted by the database, and the audit was
  right to say so.
- **The timestamp inside a message id.** A `CHECK` must be immutable, and "not from the future" is not. The
  service refuses it (D-33); the database refuses a wrong version and variant.
- **That a DM's two ids are members of its workspace**, and that a channel member is a workspace member.
  Neither is a column of the table that holds the pair.

## 12. Migration Order

`packages/db/migrations/` — ordered, additive, never edited after being applied. (D-21) The migrator
records each file's SHA-256 and refuses to start when an applied file has changed (D-86).

**A migration is one transaction.** A migration that adds a constraint or an index to a table that has
rows must leave it, with `-- purlay: no-transaction` in the file's leading comments (D-86): inside a
transaction the lock of `ADD CONSTRAINT` is held until the end, so `NOT VALID` followed by `VALIDATE`
blocks every other query on the table for the whole scan, and `CREATE INDEX CONCURRENTLY` is refused. A
file that leaves its transaction runs statement by statement and must be safe to run again.
