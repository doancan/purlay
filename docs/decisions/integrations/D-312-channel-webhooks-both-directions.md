# D-312. Channel webhooks in both directions — extends D-245

**Decided by the owner, 2026-11-14.** Extend channel integrations with incoming diagnostics and signed outgoing events.
**Authority serialization verified by Görkem, 2026-11-17.** Incoming and outgoing management take workspace KEY SHARE, then private-channel membership KEY SHARE, then channel NO KEY UPDATE, and re-read channel visibility and the current workspace role before writing. A demotion or private removal that wins refuses the stale admin context without a hook, credential receipt or webhook audit; a creator already waiting at channel admission holds authority until its transaction ends, so the authority change waits. Deterministic independent-connection regressions and mutations cover both orders and directions, alongside the existing delivery lock-order tests. No contract or schema change.

Incoming hooks keep their text-only, quiet contract. Admins may rotate a secret in place; the old secret stops immediately. Authenticated request outcomes store time, HTTP status and a fixed error category, never content or credentials.

Outgoing hooks belong to one visible non-DM channel, are configured by owners/admins and subscribe to `message.created`, `thread.resolved`, `thread.reopened`. Up to ten per channel. The setup explicitly says that message content leaves the server. Integration-authored messages are excluded, including thread events on those roots. Payloads are version 1, with a stable event id, timestamp, workspace/channel and message data.

Each delivery is inserted in the same transaction as its source change, not on the at-most-once domain bus. PostgreSQL workers claim bounded batches with expiring leases and perform HTTP outside transactions; finishing requires the lease token. Delivery is at least once, unordered; receivers deduplicate the event id. A signed test event uses the same queue. Sign `timestamp + "." + rawBody` using HMAC-SHA256; send X-Purlay-Id, X-Purlay-Timestamp and X-Purlay-Signature (`v1=<hex>`). Receivers reject timestamps beyond five minutes and compare signatures in constant time. Secrets are sealed using the credential cipher and shown only when created or rotated.

HTTPS public destinations only, no URL credentials/fragments, no redirects, checked DNS pinned to each connection, ten-second total timeout. Reuse the existing external-request policy. 2xx succeeds; network failures, 408, 429 and 5xx retry with exponential jitter for at most 24 hours. Other statuses fail permanently. Retry-After is respected within the remaining lifetime. Attempts and terminal deliveries expire after seven days; pending work expires after 24 hours. Manual retry keeps event id/body and starts a new 24-hour window. Pausing blocks claims; revoking cancels pending work. Already-started HTTP cannot be recalled. Archiving/deleting a channel/workspace blocks sends; soft-deleted messages cancel pending work. Erasure removes queued content about the person; exports include hook configuration without targets/secrets and exclude operational delivery/attempt data. Purges cascade with the channel. A partially applied chat migration set (an upgrade while chat is disabled) must not remove historical message authors from exports: people queries omit only their absent tables. Retention rechecks its age predicate after waiting for a row lock, so a manual retry is not deleted by an older candidate read.

The existing external scheduler runs the bounded dispatcher each minute and the retention sweep hourly; it reports job failures and delivery outcomes without URLs, payloads, secrets or response bodies. No Redis or new runtime dependency. Growth is events × subscribed hooks × attempts: list endpoints paginate, hooks are capped, work per invocation is bounded and rows expire.

The existing eight-statement budget for an ordinary text send stays: the channel membership guard returns the posting policy from its same query, replacing the separate policy lookup. Announcement roles are still read under the workspace lock; no cached authority or extra lock is introduced.

**Cost of reversing.** Pause/revoke hooks and revert application code; additive tables and columns remain. No down migration. Existing incoming clients are unchanged. New routes return ordinary unknown-path responses with chat disabled. No DMs, arbitrary templates, custom headers, file downloads, provider-specific payload renderers, incoming deduplication, event ordering or exactly-once claims.

Failure tests cover malformed/boundary input, tenant/private-channel authorization, role changes, rollback, duplicate sends, concurrent claims, crash/lease recovery, stale finishes, signatures, SSRF, retry exhaustion, pause/revoke, retention/erasure/export and EN/TR browser flows. A separate reviewer checks the diff against this decision before completion.
