# D-313. An issue is claimed with a command, and the board's stage is derived from who holds it

**Decided by the owner, 2026-11-18.** Several people and AI sessions work on the backlog at once. `bun run claim <number>` assigns the issue to whoever runs it and refuses when it is closed, an epic, held by somebody else, or waiting on an open issue. `bun run queue --apply` writes the stage to the board and nobody moves a card: In review when an open pull request closes the issue, In progress when it has an assignee, Backlog while a `**Blocked by**` issue is open, Ready otherwise. Closed issues are shown as Done, and open issues the board does not hold yet are added to it.

Collisions are refused where they cost a rebase. Migrations are numbered, so a second issue labelled `database` cannot start while one is under way. An issue labelled `exclusive` (one that moves many files) cannot start while another issue in a code area it touches is under way, and nothing in that area can start while it is. A code area is `api`, `web`, `database`, `realtime` or `contracts`; `infra`, `docs`, `testing` and `security` cut across all of them and say nothing about which files change. GitHub cannot assign conditionally, so after assigning, the claim reads the issue again and the person GitHub lists first holds it; the other backs off. A `D-` number is taken when a pull request is ready to merge, by rebasing on `main` and using the next free one, not when it is opened.

`.github/workflows/board.yml` runs the same `queue --apply` on issue and pull request events and daily. It checks out the default branch, never the pull request, because it holds `BOARD_TOKEN`, which can write the board (`GITHUB_TOKEN` cannot write a user-owned Project). A pull request that closes an issue nobody holds assigns its author. Without the secret the board is written by running the command locally.

**Rejected.** Moving cards by hand or with the Projects built-in automations: the status is wrong the moment something merges, the argument of D-45 and of CONTRIBUTING §7. Deriving the stage without a claim: nothing then stops two people starting the same issue. A lock label instead of the assignee: it would say who without GitHub's own notion of who. Treating every area label as a conflict: `testing` and `docs` are on most issues, so almost nothing could start beside an exclusive one.

**Cost of reversing.** Delete the workflow and the two scripts; the assignees and the board's stages stay as they are. No schema, no runtime code, no product behaviour.
