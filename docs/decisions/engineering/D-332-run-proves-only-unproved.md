# D-332. A run proves only what is not already proved: a light change, and content verified before it reached main — builds on D-203, D-226, D-229

**Decided under the owner's standing instruction to decide and proceed**, from the request that a merge take minutes and a release ten, without raising the risk. A pull request took 26 minutes, all of it the `schema` job's coverage run of 29,889 tests (the browser suites, 10–12 minutes, ran beside it); main then ran the same 26 minutes again on a commit whose content a pull request had just passed, and the release's own pull request, which changes a version and some notes, paid it a third time. Measured, not guessed: there is no single slow test (the largest file is 6% of the time); the suite is simply large.

1. **Light changes.** A pull request is *light* when every changed file is a document (`docs/`, a root `*.md`) or `package.json` with its `version` line the only line that moved. No source, test, script, workflow or dependency changed, so no test of the code can answer differently; what *can* read a document or the version is a test that needs no database, so `light-suite` runs every one of those (`bun run test:light`, about three minutes) in place of `schema`. One other file, a `package.json` change that is not the version, a patch GitHub did not send, an empty file list: not light, the whole run.
2. **Content already verified.** A commit on main is *reused* when its tree is the tree of a merged pull request's head whose own `verify` succeeded with `static`, `schema`, the browser suites and the suites per cell *run* — not skipped for a path (a matrix counts when every one of its legs, which GitHub names `browser (chromium-dark, suite)`, succeeded). Then those four are not run again; the measurements, the module matrix, the mutations and the documents are (they are cheap, and main is where the baselines are made). Or when the commit is a light change on a base that is itself reused, to depth three: a release is a version and notes on a tested tree. A rebase that changed the tree (main moved), a skipped heavy job, a failed `verify` or any answer GitHub did not give is "not verified": the whole run, as before.
3. **`scope` decides, `verify` checks.** `scripts/ci-scope.ts` reads GitHub once and writes `light` and `reuse`. `verify` (`scripts/ci-gate.ts`) accepts `schema` skipped only for exactly those two reasons and `static` and `module-suites` only for the second, requires `light-suite` to have succeeded for a light change, and refuses every skip when `scope` itself did not succeed. `ci-test-gate.test.ts` pins `schema`'s condition to those two strings, so a third way for the suite not to run fails a test.
4. **Nothing is gated less.** Every test still runs before a merge for any change that can move a code path; the coverage floor is still judged on the whole suite for them. What is no longer paid is the same proof twice. Six mutations (`scripts/mutations/scripts.ts`) break each guard on purpose: a script counted as a document, any `package.json` change called a version bump, a reused run of another tree, of a skipped job, the coverage run skippable for any scope, the light suite skippable for a light change.

**Rejected.** *Sharding the coverage run:* the floor is per file, Bun's `lcov` carries function totals and not function names, so the shards' function coverage cannot be merged exactly, and an inexact floor is a loosened one. *Fast gate before merge, full suite after it:* a red main for minutes, the floor moved after the merge. *Path filters for `schema`:* every package, script and document is read by some test; a filter is a guess about which. *Trusting a pull request's run for any commit with the same title or branch:* only the tree is the content.

**Time.** A light pull request (a release's, a documents') takes about five minutes where it took 26. A code pull request still takes the coverage run's 26 minutes — about twelve on a larger runner, which is the owner's cost to decide. Main takes about six minutes for content a pull request had passed, where it took 26, so a release is published about fifteen minutes after its pull request is opened, where it took an hour.

**Cost of reversing.** Delete the `scope` job and its `needs`; `schema` and `static` run on everything again.
