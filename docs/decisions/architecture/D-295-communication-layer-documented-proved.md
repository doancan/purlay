# D-295. The documents say what the communication layer is, a fake pair of modules proved it, and what is not built has a trigger — builds on D-272, D-283, D-288, D-289, D-291, D-294; amends `MODULES.md` §4, §9 and §10

**Context.** Steps 14b to 14l of D-283, the per-workspace grant (D-289, D-292), the degradation contract (D-291) and the scaffold
(D-294) were built in separate changes, each editing the rows of `MODULES.md` it touched, so rows written before a step landed
still said "no module calls it yet" and "not built" of what the code has. The rule of D-272 is that a document that says built means
there is a test, and one that says not built means there is a sentence about what starts it. An audit that trusted none of it
took each claim to the code (`git grep` for every file, mutation and identifier `MODULES.md` names: all present), ran the
generator on a copy, wired a fact from one fake module to another's handler, a notice to the inbox and a source to the find, and
tried to go round the guards.

**Decision.**

1. **The rows follow the code.** Steps 14h to 14j and the release snapshot's hold on `publishes` and `consumes` are marked as
   built where they were still marked as intent, and the placeholder row of the table of what a new module edits (`index.ts`)
   says that nothing is edited.
2. **What is not built is one table with a trigger and what watches** (`MODULES.md` §10): a fact published by a module of the
   product, `ports.of`, the SQL form of the entitlement function for jobs and workers (all three since built, D-289 §10, D-291 §5), the web's search groups, a runtime kill
   switch, tracing across modules, per-tenant quotas, the web scaffold of a module, the scan of ports and the wire-union watcher.
   A row whose watcher is "review" says so.
3. **The paved road's measured gaps are listed in §9** (`MODULES.md`), with the evidence of the audit: the second `module:new`, a
   module's first fact (an import cycle), a consumer's `consumes` entry read as a table, the existing tests that list no fact,
   kind or source, no way for a route to publish, the schema regenerated by hand, a feature that imports the composition, and a
   notice written under another module's kind. They are reported and not fixed here, each its own change.
4. **The idle memory bound is the owner's decision.** `budget:api` fails at 120 MiB; readings of the idle API on the machines used
   for the audit were 112 to 129 MB. Nothing here moves the bound.

**Rejected.** *Fixing the gaps in the same change*: each is a behaviour change with its own tests, and mixing them with a document
that says what is true would hide which change fixed which. *Leaving the stale rows until each step's next change touches them*:
that is how they went stale.

**Cost of reversing.** Documents only.
